**Título:** Arquitetura de Projetos IPPLS  
**Subtítulo:** Plataforma de Padronização e Gestão de Projetos Acadêmicos  
**Instituição:** Instituto Politécnico Privado Lucrêcio dos Santos

**Nível:** Avançado

## 2. RESUMO EXECUTIVO

O projeto "Arquitetura de Projetos IPPLS" é uma plataforma web robusta desenvolvida para resolver problemas estruturais no desenvolvimento de projetos acadêmicos pelos estudantes do Instituto Politécnico Privado Lucrêcio dos Santos. A plataforma implementa templates padronizados baseados na arquitetura MVC (Model-View-Controller), oferecendo três níveis de complexidade (Base, Padrão e Avançado) para diferentes necessidades pedagógicas.

**Palavras-chave:** Arquitetura de Software, MVC, Padronização, Gestão de Projetos, Plataforma Educacional

---

## 3. PROBLEMÁTICA

### 3.1 Identificação do Problema

Os estudantes do IPPLS enfrentam dificuldades significativas no desenvolvimento de projetos de programação web devido à:

- **Falta de padronização:** Ausência de estruturas convencionais de diretórios
- **Conhecimento limitado:** Desconhecimento sobre arquiteturas de software
- **Estruturas inadequadas:** Projetos desenvolvidos de forma empírica e sem organização
- **Baixa qualidade:** Projetos sem estética e funcionalidade adequadas

### 3.2 Exemplo da Problemática Atual

```
PROJECTO TLP/
├── index.php
├── home.html
├── login.html
├── conn.php
├── imagem-1.png
├── pagina-de-cadastro.html
└── etc.
```

Esta estrutura demonstra a desorganização típica encontrada nos projetos estudantis.

### 3.3 Impacto do Problema

- Redução da qualidade acadêmica
- Dificuldade na avaliação pelos professores
- Formação inadequada dos estudantes
- Baixa produtividade no desenvolvimento

### 4.1 Objetivo Geral

Desenvolver uma plataforma web que padronize e gerencie a criação de projetos acadêmicos no IPPLS, implementando estruturas baseadas na arquitetura MVC com diferentes níveis de complexidade.

## 6. FUNDAMENTAÇÃO TEÓRICA

### 6.1 Arquitetura MVC (Model-View-Controller)

A arquitetura MVC é um padrão de design que separa a aplicação em três componentes interconectados:

- **Model (Modelo):** Gerencia os dados e a lógica de negócio
- **View (Visão):** Responsável pela apresentação dos dados
- **Controller (Controlador):** Intermediário entre Model e View

### 6.2 Engenharia de Software

Princípios fundamentais aplicados:
- **Modularidade:** Separação em componentes independentes
- **Reutilização:** Templates padronizados para diferentes projetos
- **Manutenibilidade:** Estrutura organizada e documentada

### 6.3 Gestão de Projetos Educacionais

Metodologias aplicadas para acompanhamento e avaliação do progresso estudantil.

### 8.3 Camada de Apresentação (Frontend Vue 3)

- **Navbar global (`resources/js/components/Navbar.vue`)** – navegação fixa compartilhada em todas as telas públicas.
- **Footer reutilizável (`resources/js/components/AppFooter.vue`)** – adicionado para padronizar links institucionais, redes sociais e captura de newsletter.
- **Landing page (`resources/js/pages/Welcome.vue`)** – apresenta o projeto e reaproveita o footer compartilhado.
- **Template Base (`resources/js/pages/Templates/Base/Index.vue`)** – visão completa da estrutura MVC simplificada, com tabs interativas e exemplos de código.
- **Template Padrão (`resources/js/pages/Templates/Padrao/index.vue`)** – descreve camadas de serviços, middlewares e integrações REST com conteúdo exclusivo.
- **Template Avançado (`resources/js/pages/Templates/Avancado/Index.vue`)** – detalha arquitetura enterprise, módulos independentes e pipelines CI/CD.

## 10. BANCO DE DADOS

### 10.1 Modelo Conceitual

#### Entidades Principais:
- **Usuários** (estudantes, professores, coordenadores)
- **Projetos** (templates disponíveis)
- **Instâncias de Projeto** (projetos em desenvolvimento)
- **Cursos e Turmas**
- **Avaliações**

### 10.2 Esquema de Dados

```sql
-- Tabela de Usuários
CREATE TABLE usuarios (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    senha VARCHAR(255) NOT NULL,
    tipo ENUM('estudante', 'professor', 'coordenador'),
    telefone_encarregado VARCHAR(20),
    curso_id INT,
    turma_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabela de Projetos Template
CREATE TABLE projetos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    titulo VARCHAR(150) NOT NULL,
    descricao TEXT,
    imagem VARCHAR(255),
    categoria VARCHAR(50),
    status ENUM('ativo', 'inativo') DEFAULT 'ativo',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tabela de Instâncias de Projeto
CREATE TABLE instancias_projeto (
    id INT PRIMARY KEY AUTO_INCREMENT,
    projeto_id INT,
    usuario_id INT,
    nivel_arquitetura ENUM('base', 'padrao', 'avancado'),
    percentual_conclusao INT DEFAULT 0,
    status ENUM('iniciado', 'em_desenvolvimento', 'concluido'),
    data_inicio TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    data_conclusao TIMESTAMP NULL,
    FOREIGN KEY (projeto_id) REFERENCES projetos(id),
    FOREIGN KEY (usuario_id) REFERENCES usuarios(id)
);
```
